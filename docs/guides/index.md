# Guides

These are deliberately **low-stakes, conceptual and deployment-focused
examples**. They explain where Freebird's token issue/check/verify model might
fit during prototyping; they are not production blueprints, policy approvals,
or guarantees of anonymity, authorization, fairness, availability, or Sybil
resistance.

- [Anonymous feedback](anonymous-feedback.md): a conceptual one-time submission
  flow, not an anonymous voting system.
- [Token-gated community](token-gated-community.md): a small membership-gate
  pattern, not a complete identity or authorization system.
- [Public Wi-Fi pass](public-wifi-pass.md): a local day-pass/check pattern, not a
  production public-network deployment.
- [Witness integration](witness-integration.md): a future integration/demo
  concept; no witness integration is implemented.

For actual deployment constraints, read [Production
Deployment](../production-deployment.md), and for proofs see [Client Sybil
Proofs](../client-proofs.md).
